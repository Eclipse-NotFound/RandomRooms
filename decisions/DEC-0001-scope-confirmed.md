# DEC-0001 —— 项目范围与方向决策（用户确认 2026-08-17）

状态: **已确认**（用户明确答复）

## 决策

1. **v1 范围 = P0 + P1**
   - P0：房间池重掷 + 模板变异器（镜像 / 属性重掷 / 瓦片微突变 / 内容重洗）
   - P1：新土地「random_rooms」无限废墟模式 + 种子码系统 + 主菜单配置
   - 不做：P2 程序化合成的排期承诺（仍保留为远期愿景）
2. **种子/联机**：设计保留（确定性 PRNG 单点注入），**延后实现**；
   RConnect 联机联动不在 v1（涉及跨模组，需另授权）
3. **入口**：PipPage 旅行列表（复用世界地图同款 gotoLand 通道）
   - 依据：shared-knowledge/world-objects/facts/land-travel-api.md
     （gotoLand 是标准入口；dopusk/speedShtr 门控要探测）
4. **配置 UI**：主菜单集成（不是 F9 面板）
5. **部署**：涉及 pfe.swf 追加 loader 时先请示用户再动手

## 理由

- P0 最小改动最大见效、风险最低；P1 是差异化核心（roguelike 循环 + 种子）；
  P2 依赖对游戏门位/pass 语义的更深入验证，放后。
- 种子确定性是已知联机硬伤（rnd 双实例不一致）的根治方向，但不能在没和
  RConnect 协议对齐前承诺联机结果，故先做单机确定性。
- PipPage 旅行列表 + gotoLand 是唯一被共享知识验证过的安全旅行通道
  （直接 Set curLandId 会挂死）。
- 主菜单集成避免运行中热键冲突（模组 KEY_DOWN 抢在游戏前，见 input-system），
  配置在进游戏前完成最安全。

## 影响

- 设计文档 vision-and-proposals.md §9 的问题已全部落地，本节作为最终范围。
- 路线图修正：M0 验证注入点 → P0 → P1。
