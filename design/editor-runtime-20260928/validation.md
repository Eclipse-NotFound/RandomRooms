# v13.1 编辑器接入与挂墙物体：已部署验证

2026-09-28。用户明确要求具体实现并实装，另强调终端、按钮距地面有一定距离。本轮实现完整生成快照导出、正式地图编辑器审查入口、规划叠层和只读编辑稿对照，以及 v13 的挂墙摆放。未引入新的破碎地形算法，也未建立编辑器整房回灌池。

## 实际变化

- 游戏 Shift+F5 导出当前全部已生成 Location 的原始 XML，保留格网、对象、背景、options、doors、rrPlan、种子、镜像与场景参数；另附选中房、地图范围、邻房存在状态和来源校验值。原池不变，不涉及真实存档序列化。独立文件留历史，latest 用临时文件替换。
- 地图编辑器“预渲染”右侧新增“随机房审查”。入口桥接由 EditorTools 加载独立 RandomRoomsEditor.swf；根 Editor.swf、NativeScene.swf、三份游戏 SWF 与 loader 清单均未改。
- 审查直接读取完整 XML，避开原编辑器 encode 丢 rr 元数据的问题。原生静态绘图应用场景、强度、生态、镜像和城市透背景。可选择房间/邻房、缩放拖动、切换用途/D/V/生成点/炮塔意图/终端候选路径/接口，导出当前叠层 PNG。
- 切换叠层使用固定底图。编辑稿通过原编辑器 ToolsSnapshot 读取，核对同名房，在冻结原图与草稿间切换并标出格差；旧规划显示未重验警示。只核对房名，不将此对照视为跨种子来源认证；不回灌游戏。
- v13 的 term1/2/3、knop1/3、wallsafe 等挂墙物品与操作地面分开选点：安装位高一格、保留背墙，地面操作位有两脚支撑和身体空位、避开梯子。RRPopulation 的 fixture 挂装分支仅由 v13 内容规划使用，历史版本规则不变。

## 失败与纠正

首轮批量原生检查在工厂 `rrp_4_11` 壁式保险箱报告视线阻挡。调查发现原版 `Location.isLine` 即使从别的实例调用，内部仍查 `World.w.loc`。测试器因此查了错误房间。已保留 `fixture-probe-context-failed/`，修改测试器为逐目标房物理格查询、当前房额外走原生函数；**同一份候选 SWF** 四场景重跑通过。没有为迎合误报而修改地形或摆放。

第一次本地编译修正了 AS3 try/catch 返回值检查；两次启动/冻结命令曾使用错误相对路径，在运行实例或写出冻结目录前失败，改用正确工作目录后继续。成功与失败证据没有互相覆盖。
