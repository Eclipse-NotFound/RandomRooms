# 破碎房间生成：算法资料与适配评估

日期：2026-09-28。范围：RandomRooms v13 后续设计调查；本文件不代表功能已实现或部署。

## 结论与证据边界

**推荐保留建筑生成器，在其结果上加入“少量有方向、有范围的破坏事件”，用连片侵蚀和多尺度噪声改变事件边缘。** 噪声可以让缺口不规则，但它本身不知道楼层、门框、用途或炮塔。直接把整张图换成高频随机瓦片，能够增加杂乱程度，却不能单独表达“这原来是一座建筑”。这是本次工程与美术适配判断，不是外部论文已经证明的 Remains 结论。

需要分别看四层变化：表面旧损；墙/板轮廓缺角；房间之间真实连通关系变化；物件与结构的中断关系。建议前两层可普遍出现，第三层只让少量明确的破坏事件负责，第四层跟随事件布置。不能仅以空洞数量或噪声强度验收破碎感。

主调查已指出必须进一步区分物理地形、后墙擦除装饰、原生破边材质；**画面上的黑洞不等于可以走过去的缺口。** 因此本文件的“结构破坏”只指实际改变碰撞和行走表面的操作。后墙缺口可以用另一张连续噪声掩膜聚集分布，保留旧楼层的背景条带，也可以在不新增危险落差的情况下显著改变观感。具体原版样本与计数由主调查记录，本文件不把这些视觉方法混称为删墙。

本子调查阅读了算法作者论文、项目文档，以及本模组当前源码。**没有核验原版所有房间，也没有证据证明原版采用 Perlin、CA 或 WFC。** 原版瓦片、对象与具体示例应以本轮主调查的游戏文件证据为准；下文场景适配均为待原版样本校准的建议。未改生产代码、配置和 release，未启动游戏。

## 五类方法怎样适配

### 1. 连续噪声、多尺度噪声：适合决定破坏聚集在哪里

白话：让附近格子的随机值彼此相近，就容易出现“一片坏、一片好”；叠加大小不同的波动，才有大破口与小缺角共存。算法依据见 [Perlin 论文](https://mrl.cs.nyu.edu/~perlin/paper445.pdf) 与 [FastNoiseLite 文档](https://github.com/Auburn/FastNoiseLite/wiki/Documentation)。

**适配建议：** 噪声作为建筑表面的受损程度场，不直接决定整张图哪里是墙。先选中一个墙段、楼板段或外墙暴露区，再限定在它内部切掉高分格子。大尺度控制破坏斑块，细尺度只改变边缘；不对所有格子同样处理。可以用 `事件影响 + 低频噪声 + 少量高频噪声 - 保护权重` 排序，在预算内选择瓦片。

关键控制：斑块尺度、受损占比、边缘起伏、横纵比例、噪声层数、细节幅度、与屋顶/外墙/管线的距离。应把“更多破坏”和“更碎的边缘”分成两个参数。前者扩大或增加事件，后者改变边缘粗细；让两者共用一个滑块会很难判断效果。

风险：阈值噪声可能出现圆团状孔洞、薄片和悬空单格；高频占比过大会像撒盐，强坐标扰动会让楼板像融化。第一轮不建议扭曲整座建筑的坐标。可以只扰动事件边界，且保持长的水平楼板和竖直墙段作为参照。

### 2. 元胞自动机（CA）：适合自然侵蚀区或破坏边缘的局部整理

白话：每格根据周围格子的多数状态反复调整，零碎点会聚成块，窄口可能消失。上述洞窟论文把它用于岩石与通道，并单独处理区块连通。[Johnson 等，§3](https://pcgworkshop.com/archive/johnson2010cellular.pdf)

**适配建议：** 仅在已选破坏区域内运行少量迭代，或用于下水道外侧的土石、淤积轮廓。CA 不宜在每层建筑的全部墙面反复执行。保护格必须在每一轮参与计算时保持固定；只在最后把门梯贴回去，可能留下不自然的方块补丁和虚假的可达关系。

可控参数：初始破坏率、邻域形状、生成/保留阈值、迭代次数、固定边界、允许修改的瓦片集合。建议使用四向或带水平偏好的邻域对照八邻域；这里的方向偏置是建筑适配提案，不是原论文结论。

风险：容易把建筑变成洞窟，磨掉直角和层的辨识度；同一初始破坏率并不保证最终破坏量相同。必须记录最终面积，不能仅比较初始随机率。CA 的“空地连通”还不包括重力、梯子和落差。

### 3. 有偏随机游走、连片侵蚀：最适合第一轮结构破坏原型

作者代码证明挖掘者可以有方向记忆、转向频率和不同笔刷式行为；本项目可把“在岩石中挖路”改成“从事件源沿允许墙段吃掉结构”。[Liapis 配套代码](https://github.com/sentientdesigns/constructive)

**适配建议：** 在墙角、暴露外墙、已有裂口、楼板接缝等候选位置选少量起点，让生长前沿优先扩展到附近的可破坏格，而非每一步在全图重抽位置。可使用短的有偏随机游走，也可维护一个破口边界队列，按方向和材料权重选择下一格。后者更容易精确限制被删格数。它们是可读、可调的形状构造方法，不是材料力学模拟。

一组事件可以同时产出：裂口、残墙、下方碎屑落点和中断的装饰线；需要各自的合法位置检查。碎屑应有支撑或作为无碰撞背景，不能因“看起来掉下来了”而把入口堵住。

关键控制：事件数、单事件面积/半径、方向保持概率、分枝机会、笔刷宽度、向下偏置、沿墙/沿接缝偏置、最大穿透厚度。大缺口用少数大块，不用几十个独立小孔。边缘侵蚀与内部贯穿应是不同事件类型。

风险：单条游走会留下虫道；强轴向游走可能像管道；跨保护区拒绝某些格后，最终删格集合也不再天然连成一片。应检查破口形状、孤立碎片和被切开的支撑，而不是只检查随机游走本身连续。

### 4. WFC 或局部约束拼接：适合最后修边，不宜第一轮替换整个生成器

WFC 的长处是局部图案合法，且能在已有固定结构周围补全；矛盾仍需处理。[Gumin 原项目](https://github.com/mxgmn/WaveFunctionCollapse)

**适配建议：** 当需要选断墙边缘、残留梁头、开口周围的材料过渡时，可将完整结构、缺损边、瓦砾边作为有限状态，固定大轮廓后再决定局部细节。第一轮可以用简单邻接规则完成同样的有限目标，不必先引入完整求解器。

关键控制：场景专用状态集、合法邻接、样式权重、固定格、允许范围、最大重试次数。横版环境有重力，不能无条件旋转上下；天花板和地板的图案也不能只因像素旋转合法就互换。

风险：样本收集和语义标注成本高；只给破碎样本会处处破碎，少给样本会重复；局部合法仍可能有封闭孤岛。若将来从原版提取局部样式，需明确只是抽取统计/邻接规律还是复制局部块，避免无意改变用户选择的从零生成路线。四场景应分别建规则，不能用混合样本重新引入素材串场。

### 5. 结构图与几何约束：负责让破坏仍然是一座可探索建筑

图的白话含义是“哪些空间相邻、通过什么连接”；它不负责墙边有几个缺口。分开表示结构与空间已有研究依据，横版可玩性还需要角色运动限制。[Dormans 论文首页](https://www.pcgworkshop.com/archive/dormans2010adventures.pdf)、[Tanagra 论文](https://ojs.aaai.org/index.php/AIIDE/article/download/12379/12238/15907)

**适配建议：** 在随机选择破坏事件时，保留楼层标高、入口、门梯、结构片段和用途的语义。允许事件有不同后果：仅缺角、开观察孔、横向合并、打通局部楼板、倒塌后形成可返回绕路。不能所有事件都等价成“再加一个洞”。选择事件时可以随机，接受事件时应检查结果。

这不意味着恢复固定从左到右主路。用户可以从任何实际开放入口进入；检查应针对所有这些入口的往返连通。不要先破坏任意位置、再用统一底层隧道修复，否则会重新造成之前的路线同质化。失败时回退该事件或缩小它，不必重画整张建筑。

## 与当前 v13 的接入关系

当前真实流程是：建筑规划与门梯/窗口、通行审查 → 人口与安保 → 家具 → XML 元数据。具体见 [RRSynth.as:29](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRSynth.as:29>) 和 [RRArchitecture.as:41](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRArchitecture.as:41>)。`RRCook` 不应再雕刻最终地形，源码开头已有这一约束。

建议把新增工作拆成两次：

1. **结构破坏**放在建筑结构产生以后、门窗/最终通行审查以及 v13 内容布置以前。每次修改保留差分，失败只撤销本次事件。门梯已规划部分作为保护或必须重建的对象；不能只删 grid 而留下 doors/ladders/links 的旧记录。
2. **表面破旧与无碰撞碎屑**放在碰撞结构冻结之后，服从场景材料和家具占用，不重新影响已审核的炮塔、终端和通路。

若短期只能放在 `plan.build()` 之后，必须重新执行完整结构审查并同步各对象列表；“函数放在这里方便”不能替代这些处理。长期更清楚的接口是把结构构造、损坏、对象安装、审查分开。

目前 `regions`、用途区域和 `RRContentPlan.belongs()` 仍主要依赖子矩形范围；家具候选依赖 floor 等原有边界。虽然实际放置会检查实体和支撑，仍不能仅删瓦片就宣称语义同步完成。[RRContentPlan.as:38](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRContentPlan.as:38>)、[RRContentPlan.as:69](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRContentPlan.as:69>)、[RRFurnish.as:129](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRFurnish.as:129>)、[RRFurnish.as:275](</D:/Program Files/Steam/steamapps/common/Remains/mods/RandomRooms/src/rr/RRFurnish.as:275>)。

建议保留两个概念：原设计用途区域（破坏后仍可看出这里原来是办公室）；最终有效空间与可站立表面（决定当下放置和战斗）。大范围拆墙后，需要合并或限制能相互支援的遭遇预算，避免原来几间各自合理的 D 值叠成同一场过量战斗；同时不要因为一个观察孔就把全部 D/V 归为一组。

|---|---|

## 可控参数建议

以下是**首轮对照的起始范围**，不是原版统计，不是已经调好的正式值。应在原版样本的破口宽度、层间高度、保留直边长度测量后调整。

| 参数 | 控制的观感 | 首轮建议 |
|---|---|---|
| 事件数量 | 是少数集中事故，还是到处小旧损 | 每 48×25 合成房 0–2 个结构事件；表面损伤另计 |
| 结构删改预算 | 整体受损多少 | 以允许受损的结构瓦片为分母，试 0%、5%、12%；不要用总画面面积冒充破坏率 |
| 事件范围 | 大缺口与小缺角 | 先试宽 4–10、高 2–6 格的局部区域；最终可删面积受预算和保护限制 |
| 轮廓尺度 | 片状还是颗粒状 | 低频为主，2–3 层噪声，细层幅度明显更低；与一层高频作为反例对照 |
| 边缘侵蚀深度 | 残墙厚度与缺角 | 从暴露边向内 1–2 格；贯穿厚墙作为独立事件 |
| 转向/分枝 | 裂口是细长还是团块 | 游走短程、少分枝；与边界队列按面积生长对照，不把长隧道当坍塌 |
| 保留直段长度 | 能否读出原有楼层/房间 | 从现有建筑上选几段重要墙板锁定，具体长度按场景采样，避免统一百分比硬造风格 |
| 结构与表面耦合 | 缺口附近是否有配套残迹 | 结构事件输出自己的装饰候选；允许远处有少量独立旧损 |
| 场景权重 | 破坏是否符合场所 | 城市外墙/屋顶、工厂设备区、下水道潮湿边缘、避难厩局部失修只是候选语义，须以原版证据定案 |

破碎程度应独立于 D/V。最多根据场所用途与破坏形式弱影响某些候选位置；“旧损高所以敌人和保险箱必定多”不是用户已经决定的规则。

## 最小对照建议

不要第一轮同时改变房间数、用途、材料和敌人。先固定 4 个真实 v13 底图（每场景 1 个），冻结最终基础网格与对象输入，而不只是给各算法写相同种子。随后分别抽取独立的 `damage` 来源，保留每次差分。

第一组只比较**几何轮廓**，在同一删格预算和同一可受损区域下出 4 列：

1. 无破坏基线。
2. 独立白噪声删格（仅作验证“随机更多是否足够”的反例）。
3. 局部多尺度噪声侵蚀。
4. 推荐的事件选址＋连片侵蚀＋少量边缘噪声。

第二组只取 2 个明显受损局部，加入 CA 与简单局部修边作放大对照。WFC 先做能力与规则成本验证，不必第一轮建完整四场景样式库。两组都应展示原图、删改区域、最终纯碰撞图、正常材料图；让缺口形状与贴图装饰的贡献能够分开看。

视觉判据：是否还能认出楼层与原房间用途；大中小缺口是否分级；损伤是否有集中位置和方向；有没有胡椒点、虫道、融化轮廓；正常区与受损区是否有对比。至少展示多个未经挑选的固定种子，不能只展示最佳图。

机器检查：端口与镜像不变量、所有开放入口往返、干路、门梯/炮塔支撑、终端身体遮挡与操作路径、悬空单格数、删改预算、战斗连通区域压力。视觉觉得合适后再做原生移动和枪线验证；不把 HTML 示意或图论通过称为游戏内通过。

**优先推荐第 4 列作为后续原型，保留第 3 列作低成本比较。** CA 可留给自然侵蚀局部，WFC 可留给边缘语法。整个顺序只是一项建议，本轮尚未改变生成器。
