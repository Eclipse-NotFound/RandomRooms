# 原版的破碎感：地形、后墙与材质的分层调查

2026-09-28 · RandomRooms v13 后续设计调查。**本轮未修改生成器或部署文件。**

[打开图文调查页](index.html) · [逐房原始数据与文件指纹](native-evidence.json) · [算法一手资料及适配评估](algorithm-sources.md)

## 判断

原版最有用的规律是：**先让人看得出原来的建筑或地下构造，再用几处有尺度、有方向的缺失打断它，最后叠加破边、后墙裂口与残留物。** 建筑秩序与局部失序之间的对比，比全图随机程度更重要。

“噪声更大”可以拆成三种完全不同的改变：损伤覆盖更广、单处缺口更大、边缘更细碎。原版同时出现几层高的大破口和很小的崩边，不能用同一个删格概率表达。某些原房近乎完整，某些只剩几段楼板；这说明应允许合成房之间有强烈差异，不能让每间都平均受损。

这属于根据实例作出的设计解释。原版主要构造已经写在房间 XML 中；目前没有证据表明原作者用 Perlin、元胞自动机或 WFC 生成这些轮廓。我们要复现的是它的构图规律，而非认定它使用某种算法。

## 调查范围与方法

- 逐项扫描实际 1.02 外置四场景共 **192 个房间记录**：工厂 55、避难厩 49、下水道 23、城市 65。普通池分别 40、32、22、26；其余为入口、街巷/屋顶和专用房。普通池用 `options.tip` 为空定义。
- 精读 **16 间**原房的网格、后景对象与材质，并查看原生渲染；本轮新渲染 9 间，其中屋顶背景条件单独修正复拍，另复用已保存的 7 间原生截图。完整图片与 XML 清单保留在本目录。
- 统计的是房间库里的作者配置，**不等于玩家遇见概率，也不是破碎程度评分**。实体格只统计内框 x1–46、y1–23，首字符 A–T；门、家具、薄梁、斜梯另看。
- 渲染使用独立 AIR 实例，入口选项改成展示用 `beg0`，删除 `en*` 通用敌群占位并关闭自动刷怪；具名生物/陷阱仍可能出现。未改参考房网格与后景布置。外圈接口由单房地图封边；截图不用于证明原版入口路线或刷怪密度。
- 全房图关闭玩家视野遮罩，并只画房间显示层，透明区域落到深色底板；不能把黑洞当成原版永久黑色背景。正常视角图片另保存在捕获目录。
- 城市屋顶 46 原本由 `Land` 的 `ramka=6` 得到 `backform=2`。首次通用展示没有这个条件；首轮第 8 张不用于屋顶背景结论。独立复拍显式恢复 `backform=2/transpfon=1`，几何未改；仍不声称复现完整城市相邻上下文。

## 一、破碎感至少有五个来源

| 层次 | 原版如何做 | 对玩法的影响 |
|---|---|---|
| 大轮廓缺失 | 楼板大段消失、墙只剩短段、跨层开敞、洞穴吞入设施 | 改变可走路线、落差、视线和掩体 |
| 残存结构 | 同高楼板残段、梁头、斜梯、梯架、短墙；部分保留旧楼层背景条带 | 仍能读出“原来有一层”；梁梯可能提供实际落脚或返程 |
| 材料与破边 | 普通混凝土 C → 破损混凝土 D → 裂纹 E；岩石 G、泥土 H、苔墙 L 各有遮罩 | 有的仅改变外形；有的同时改变耐久、破坏阈值，不能一概当贴图 |
| 后墙破洞 | `hole*` / `chole*` 擦除背景，不删除前景碰撞 | 可以显著增加破旧感而不增加掉落风险；背景梁架不自动可踩 |
| 散落与中断 | 底部堆瓦砾、碎窗、锈蚀、渗水、露出的管道；原家具残留在小平台上 | 大量是装饰，也有真实对象；应按类型分别检查遮挡/碰撞 |

**同样的“看起来黑了”可能表示三件事：背景被擦掉、实体使用裂纹材质、真正没有地板。** HTML 的地形层可帮助区分前两者与最后一种；它显示 XML 地形，不包含门/家具运行时碰撞，也不是通行验证。

## 二、城市废墟：保留楼层痕迹，破坏跨越楼层

最清楚的对照是城市 51 `ко.кабинеты`（办公室）与 26 `ко.разлом`（断裂）、45 `ко.развалено3`、60 `ко.развалено2`。

| 原房（0 起算） | 可复核观察 | 可吸收的设计规则 |
|---|---|---|
| 51，rooms_mane.xml:5198 | 内框有 170 个实体格；y8/y16 楼板仍大体连续，办公室用途清楚。仅 1 个 hole、2 个 heap | “较完整但破旧”应保留，不让每间都变大废墟 |
| 26，:2648 | 92 个实体格；y8 缺 x18–21、26–33，y16 缺 x17–24、28–30，缺口上下错位；边侧带门房间仍在。3 个 hole、5 个 heap | 缺口可跨层而不必笔直贯通；完整侧室与塌落主腔互相衬托 |
| 45，:4646 | 内框仅 14 个实体格；y8/y16 大量 `_A` 是背景条带，并非整条实体楼板。保留若干梁、斜梯、短墙。4 个 hole、12 个 heap | 即使删去大部分前景楼板，背景仍可提示旧层高；少数残段形成可辨的废楼 |
| 60，:5987 | 51 个实体格；y8/y16 的断板、短墙和梁各不相同。5 个 hole、9 个 heap；中央两条 F 杂木实体与其他混凝土形成材料反差 | 楼层对齐与断口错位可以同时存在；不要把每层破成同一种模式 |
| 0，:2 | 44 个实体格；顶部仍有带门储物室，中部板块较零散，地面集中瓦砾。4 个 hole、11 个 heap | 大空腔里仍留原用途的房间、设备和落脚台，空间不是无内容的空洞 |
| 46，:4744，屋顶专用 | 建筑集中在下部，顶部是室外；屋面有完整、崩边、缺失段。不能用普通室内的满幅后墙渲染理解它 | 破坏遵守屋顶/室内/街巷语境；屋面缺损不等于每间再挖一个中井 |

这些实体计数不包含原生梁、楼梯、门和家具，所以 14 格不代表只有 14 格可站立。也不能从一个最破的例子推导整个城市都应如此。

城市普通池 26 间中有 25 间使用 `hole*`，20 间使用 `heap*`；22 间含 D，20 间含 E。破旧表面覆盖很广，重度空间崩塌则是另一项选择。瓦砾经常集中在下部，断口与后墙洞大致呼应，但没有证据表明它们由真实坍塌模拟产生。

## 三、工厂：规则设施与局部塌方并存

工厂 16 `цех1`（rooms_plant.xml:1531）保留大跨度车间、机械、钢架和规整附室；它的破旧感较多来自材料和设备。不能把大车间本身视为坍塌。

工厂 54 `обвал`（:5624）是很有用的极端样本：上方仍是规整房间，下部由不规则岩体、裂纹块与残存基座交错组成。内框实体包括 C=103、D=43、E=50、G=153、A=6、B=48。没有 `hole/chole` 或 `heap` 装饰，依然强烈破碎。

这说明它的效果很大程度来自**几何与材料交错**：破损沿集中地带向内部深入，残留块有宽窄和长短变化，几格厚的压顶与底座包围空腔。50 格 E 仍然是实体，不是 50 格空气；其中很多黑色裂纹不能算已塌掉的通道。

工厂普通池 40 间中，13 间使用 `chole*` 后墙洞，0 间使用 `heap*`；24 间含 D、22 间含 E、7 间含 G。建议用集中塌方、局部板/墙缺角和工业后墙破损，保留机械区、框架和正常车间。不要默认套用城市的满地瓦砾素材，也不要把极端塌方当作所有工厂房的标准。

## 四、避难厩：金属设施与自然岩体的交界

普通 32 间里，只有 4 间使用 G 岩石，恰好对应精读的四个洞穴样本；这是房库计数，不是 12.5% 生成概率。

- 9 `пещера2`（rooms_stable.xml:881）：上部规整服务区，下部宽阔岩洞；金属竖架穿过洞腔，墙板、岩顶与底部土石相接。直边与不规则边的反差非常明确。
- 17 `пещера`（:1864）：大部分是岩洞，仅右侧嵌一段设施；空腔里存在分离的岩台、块岛。不是从密集矩形房逐个拆隔墙就能自然得到的构图。
- 22 `пещера3`（:2367）：左下金属设施仍完整，上部自然洞腔和积水侵入，两种空间占比不对称。
- 48 `пещера4`（:4985）：内框 G=384、H=88，没有 J/K 金属实体；可作为纯洞穴极端，与 20 `зал` 的完整金属大厅形成对照。

**建议保留“常规设施”“设施与岩洞相接”“主要为洞穴”三种不同侧重。** 自然轮廓可以采用更强的连片随机，而规整金属部分继续沿建筑规则生成。原版存在视觉上分离的岩台，不宜以现实受力模拟为验收标准；需要的是可理解的横版空间、合理大小和实际可达落脚点。

## 五、下水道：厚壁与潮湿边缘，不是城市式断楼

18 `туннели`（rooms_sewer.xml:2966）内框 482 格实体全为 L 苔墙。画面很粗糙，但把贴图去掉后，大多数是长直边、厚块、柱段与错开的水平通道。9 `туннели4`（:1507）也保留明显工程管道与楼梯；19 `слив2`（:3096）是大水腔配两侧服务与交通空间，不是碎洞塞满全图。

普通 22 间全用 L；没有 `hole/chole` 与 `heap`；配置了大量 `potek`、`plesen`、`moss`，并有粗管、排水口和局部露出的设备。**部分“毛糙”由苔墙材质与遮罩提供，地形本身仍相当有秩序。** 对它全面使用高频挖洞，很可能反而远离原版。

建议随机改变厚墙的局部退缩、通道宽窄、土石侵入区与潮湿分布；保留工程直边、池底和干路。不要把“侵蚀”当作已证实的作者制作过程：这只是适合生成器采用的形状解释。

## 六、渲染源码解释了为什么方格能显得破碎

1. `Location.buildLoc`（:560 起）从 XML `<a>` 逐格调用 `Tile.dec`。第一字符与后缀分别查 `Form.fForms/oForms`；这不是运行时噪声雕刻。
2. `AllData.d.mat` 区分前景和背景材质。D 使用 `tConcreteD + maskDamaged + tSkol/maskSkol`；E 使用裂纹纹理配同类崩边；G 使用石头遮罩，H/L/N 使用相应土石/粗边遮罩。
3. `Location.tileKontur`（:2388）根据邻格实体、背景与梁判断边角；`Grafon.setMCT/drawKusok`（:764/:783）选择遮罩角块，再把连续纹理裁入这些边缘。视觉边不是每个方格都画硬矩形。
4. `AllData.d.back`（:6819 起）定义 `chole*`、`hole*` 的擦除资源和 `heap*`。`BackObj`（:86 起）加载纹理/擦除图，部分资源随机选帧或镜像；`Grafon.drawLoc`（:543 起）先擦掉背景 alpha，再回写后墙透明度。不会在这里删除 Tile 碰撞。
5. `AllData` 中 C/D 均 hp1000、thre100，而 E 为 hp150、thre10；D 不因看着破就更脆，E 则确实更弱。F 是杂木/破烂实体，hp40、mat3，不能误当玻璃。实际能否打穿还受 `Location.hitTile` 的场景保护与武器地形破坏值影响。

上述行号针对 `game-reference/decompiled/1.02/src102/scripts/fe/` 当前源码。这里讲的是确定读取到的渲染/碰撞区别，不是凭截图推断。

## 七、当前 v13 为什么仍显规整

| 当前实现 | 对破碎感的限制 |
|---|---|
| `RRArchitecture.addSceneFeatures`，:574 起 | 城市特定构造只尝试 1–3 处、宽 2–4 格的楼板替换，并用完整薄梁接住每个缺口；没有跨层成片的事件 |
| `RRFurnish.facilities`，:238 | 城市 `hole` 要求子区域宽、高都至少 10 格；大部分低层高房直接被筛掉，合并空间仍按子矩形摆设施 |
| `facility`，:160 | 装饰必须完全放进同一矩形且包围范围无实体；大型后墙洞无法像原版那样跨过楼板背后 |
| `dressMaterials`，:652 | 城市 D 材料按固定 x/8、y/6 分段取模选区；材料斑块没有跟随实际破口；工厂也只在部分外缘换 D |
| 空間类型 | 避难厩仍主要为金属矩形设施，没有原版四种洞穴这类明显不同的主空间体系 |

因此改进应同时处理构造、背景覆盖范围和材料关联。单纯提高现有“小缺口”的数量，仍会得到整齐房间里更多相似的小破口。

## 八、推荐的生成方向

**主方案：原有建筑 → 随机破坏事件 → 连片生成破口 → 小尺度修边 → 配套背景与残留。** “事件”是生成器的构图单位，例如局部塌方、跨层断裂、墙皮剥落或岩洞交界；不需要模拟真实建筑力学。

1. 先决定这间是大体完整、局部破损还是少数重度破碎，并选择符合场景的表现方式。让不同合成房有明显差别。
2. 保留若干识别线索：旧层高、连续墙段、金属设施核心、厚水渠边等。损伤中心、范围、方向随机选，不固定在合成房正中。
3. 用有方向的连片生长控制大破口；用低频连续噪声让邻格一起变化，再叠加少量细噪声改变边缘。把删格、换成易碎实体、保留梁、只擦后墙作为不同结果。
4. 同一事件关联断口材质、残留背景条带、背景梁与下方碎屑，但保留少量独立旧损。后墙破洞可以跨越原子房边界，被前景自然遮住。
5. 岩洞使用独立的土石区域规则，可用局部元胞自动机或随机生长；不要让它把所有金属房磨成圆洞。城市废楼优先保持楼层参照，水渠优先保持池底与干路。
6. 结构确定后重新安排门梯、实际落脚面、家具、敌人和炮塔；重算终端接近路径与战斗空间压力。仍允许任意开放入口进入，不用统一底层通道修补所有失败。

算法具体参数、一手来源与风险比较见 [算法报告](algorithm-sources.md)。WFC 更适合将来做破边邻接，不建议先替换整个生成器；纯白噪声只适合很细的表面颗粒或对照组。

## 九、下一步最值得做的对照（尚未实施）

先冻结相同 v13 底图，比较三层贡献：**仅后墙/表面破损 → 仅实际结构破损 → 两者结合**。再在相同允许区域和实际删改预算下比较独立删格、连续噪声与推荐的成片事件方案。单纯给不同算法同一个种子不能保证底图相同；本轮采用 KB-000045 r2 中这一条窄范围方法提醒。

先做城市断楼、工厂塌方各一组；避难厩岩洞作为不同空间类型另做，下水道仅加局部边缘变化。对照要展示多张未挑选种子、原生材质图和地形图，不能用“洞多了”代替视觉判断。

验收分开看：建筑/场景是否仍可辨、受损是否有大小层次、正常区与破损区是否形成对比；所有开放入口是否可往返、污水必经干路是否保留；门梯和炮塔是否有支撑、终端能否接近、原来分开的敌群是否因开墙而叠成过量战斗。**破碎程度独立于 D/V**，这轮没有新增两者必然关联的设定。

局部噪声与事件参数仍需原型验证；本轮结论是有原版依据的实施建议，不是已经验证的最终算法效果。
