## 结论：问题来自三层

1. **来源误用**：把“原版类可运行”当成“适合四类普通探索区”。例如工厂 eqd、下水道 necros/transm、四类 cturret，以及 moln1/elpanel/basechest 等都缺少相应普通生态依据。
2. **组合误用**：敌群、警报、机器人舱、机关分别随机；即使单项有原版来源，组合仍会跨生态。家具也有相同问题，例如工厂办公室用 table2，避难厩生活组用 poster。
3. **构造同质化**：四类统一整房矩形切分、梯子连接、随机小平台。sceneForm 大多只改变第一次切割。强制每间城市合成房带室外、每间下水道带同款小池，进一步限制差异。

用户已确认 Q1：**按原版生态与空间用途区分，允许合理共用**。Q2 地图级城市建筑/街巷/屋顶分区仍待回复；没有把未答选择视为授权。

## 生态：先决定谁占据房间，再决定配套内容

依据 `fe/loc/Land.as:980–1018`、`Location.as:1425–1723`。

| 场景 | 常规大型主群 | 关键约束 |
|---|---|---|
| 工厂 biom0 | 尸鬼、掠夺者、机器人；高难少量斑马 | eqd 不属于工厂；厂内固定炮塔也确实存在 |
| 避难厩 biom2 | 尸鬼、机器人、掠夺者随难度转奴隶主；高难少量斑马 | eqd 仅机器人生态且 locDifLevel≥12；激光机关与机器人生态绑定 |
| 下水道 biom1 | 大型主群为尸鬼 | 伴生蝎子、黏液、蚂蚁、老鼠，飞行/挂顶生物与水中鱼；没有通用终端、商人、机器人舱 |
| 城市 biom3 | 奴隶主、佣兵、天角兽；高难少量斑马 | 掠夺者/尸鬼是有具体上下文的少量房间特例，不能反客为主 |

共享知识旧文 `entities/discoveries/enemy-ecosystem-entip.md` 的城市 0/1/5/6 与当前 1.02 源码不符，采用前应纠正。原版会在 `Land.setLocDif` 覆盖 XML 的 entip；生成器不能只写 options 然后假定警报等后续刷怪也遵循它。

`Location.createHidden:1333–1355`：机器人生态可以生成 robocell，掠夺者/奴隶主可以生成 alarm。它们在房 XML 中零出现也不能误删。反过来，城市随机 robocell 会通过 `Interact.genRobot:1472–1482` 间接引入机器人。

小生物、飞行、挂顶和 lov 陷阱分别由独立原版槽位解析；不能全部当落地大型敌人。黏液地雷通过原版随机解析传入型号10；显式地图对象须写 `slime tr="10"`。`Unit.create` 的 `node.@cid` 来自 AllData 单位定义，不能误认为读取地图对象的 cid；原版实测已揭露该区别。原版型号、技能、掉落和实际交互继续由宿主类负责。

## 材料与用途

| 场景 | 常用前景组合 | 环境布置重点 |
|---|---|---|
| 工厂 | C 混凝土、D 破损混凝土，局部 E/F | 高窗、梁架、机器成组、装卸区木箱和货架、单独控制附室 |
| 避难厩 | J 金属墙、K 金属构件、A 钢 | N/P/Q/R/O 后墙分带，生活舱与公共廊、维修夹层、医疗设备集中 |
| 下水道 | L 苔墙、M 锈金属、I 砖、A 钢，局部 F | 粗管连续、排水口与污迹有方向；干检修道、泵房和池岸分工 |
| 城市 | N 建筑墙、D 破损混凝土，局部 E/F | 窗带、断墙、残楼板、阳台与塌口堆积；家具反映原建筑用途 |

`AllData.as:6428` 与 `:6584`：首字符是前景材料，其后是另一张后墙/对象表。后墙 H 是锈金属，不是民居墙纸。E 裂缝墙 HP150、F 木板 HP40，不宜无差别替换必经承重楼板。D 的耐久与 C 相同，可用于成片破损构件。

外置明显差异：plant table2=0/55，stable table2=20/49；stable poster=0/49。plant woodbox=21/55；sewer mcrate2=12/23；mane mcrate2=45/65。普通金属柜、箱、管线、部分电控本来就是共用资产，应按用途使用。

门也不能一场景只剩一款：工厂有普通门、控制室金属门、大型设备门；避难厩生活区用 stdoor，服务区也有 door1b/door2；下水道多数通道开放，维护间才加门；城市玻璃应组成建筑立面，而非在任意薄墙随机打洞。

## 空间：不同的构造顺序

普通房非实体格比例中位数：工厂76.8%、避难厩65.5%、下水道60.8%、城市室内82.1%。这只反映疏密，不能代替通行验证。按 `AllData.mat.diagon` 解码，有斜楼梯的普通房分别24/40、25/32、11/22、18/26。

- 工厂：生产大腔周边附室；仓库与高装卸台；厚设备基础与检修翼；少量明确用途长井。
- 避难厩：公共廊服务一组生活/办公单元；真正环绕开放中庭的侧翼；厚墙包围的机房和短交通带。
- 下水道：干燥折返管网；泵房和底部沟渠；较深蓄水池及干岸/桥；局部受损管沟。原版8/22普通 XML 无显式水，不能每房强制同款池。
- 城市：完整室内功能楼层；大片坍塌腔与残楼板；街隙桥/阳台；屋顶设备小建筑。原版 `Land.as:239–268` 按地图坐标选择 roof/pass/passroof，室内默认 tWindows，只有7个 passroof 房用 sky；现行全城 sky 是错误。

继续保留：从头生成、任一实际开放边口可进可回、无限向右向下、下水道必经干路。通用低层切割/碰撞检查可以共享；生成操作顺序和空间用途不能继续一套公式。

## 本轮已实现的开发版本

开发包为 `build/RandomRooms-v11-dev-8.swf`（44751 B，SHA256 `EFBFB2615A272BA46FD58D5AC890253833CC56F1319F0B55AA61ACFF3DA4EEA9`）。正式入口仍是 v10；没有部署此开发包，也没有修改游戏本体、真实存档或其他模组。

- `RREcology` 先按场景、原版实际难度与地图格奇偶确定占据者，再选择大型敌人、小生物、飞行及挂顶生物和陷阱。`RRGrowth` 在原版难度处理后恢复所选生态，避免警报等后续逻辑重新跨界。地图中黏液地雷的型号修正为 `tr="10"`。
- `RRPopulation` 将警戒、隐藏设施与同房生态绑定；去除缺少普通场景依据的特殊敌人及装置。医疗、厨房、维修、控制等设施按空间用途安排，保留普通共享容器与家具。
- `RRArchitecture` 分别实现工厂三类、避难厩三类、下水道四类构造顺序，保留通用边口协商。新增原版斜楼梯，保护整条楼梯不被后放梯子截断；门必须有门头与底座。下水道可为干房，也可有沟渠、泵房或较深蓄水池；必经路线另做干路审计。
- `RRScene/RRFurnish` 按用途选择材料、门与成组家具；工厂配置梁架、高窗和机器，避难厩配置金属内壁分带与生活设施，下水道配置连续管线、池岸、排水口和污迹。
- 城市已经改正敌群和设施边界，并恢复普通楼内的 `tWindows` 背景与原版 `transpFon` 行为，当前屋顶分支仍用 `sky`。城市地图的建筑/街巷/屋顶编排尚未改写，依赖 Q2。

实景对照见 [generator-v11-investigation.html](generator-v11-investigation.html)：12间原版参考、工厂/避难厩第一轮6间生成房、下水道深池修订4间。图像来自实际游戏渲染，未重绘；工厂/避难厩图片不冒充最新内容刷新实测。城市暂仅列原版参考，避免用旧布局冒充新设计。

深池初次测试已实际到达池底，却把“水中未处于站立状态”误判为没有到达，未执行返程；失败另存 `deep-water-initial-failure/`。修正测试的水中到达条件后，用相同XML和碰撞规则完成返岸，没有修改水池、梯子或角色坐标。

三类成功扩张均由5×5到8×8，原房XML、镜像及原有内容对象不变，已搜容器没有重新装满。驾驶器只用正常方向、爬梯、跳跃和行动键；测试有持续伤害保护。此结果不代替长期扩张、联机、战斗平衡或正式版本集成验证。

当前批量XML SHA256：单房 `65616F4B2C2D3E60DA58CCB82D0C33CA4A89C3F4579D7CA45C7B029B674E7290`；64房地图 `BFD9B822F4ED7894E0A6CB64F6ADD22763BFFADA24056F9C3AC0FF5A6DB179D7`。较早批次独立封存，不能混作当前源码结果。

构造拒绝原因也进入批量证据。曾出现“测试全通过但蓄水池构造全部被淘汰”的问题：上口长梯和池内梯占尽横向空间。已将上口接检修廊、池内下降优先靠岸，并尝试不同池宽；本批32间下水道出现3个深池。该频率是本批样本结果，不是承诺的刷新率。
