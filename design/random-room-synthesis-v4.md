# RRSynth v4 —— 结构语法生成：从"拼贴原版"到"理解并重组"

> 状态：规划（头脑风暴完成，含实证数据）
> 日期：2026-08-20
> 触发：v3.6 实机反馈 ——"随机房变成原版房间拼贴，虽符合原版设计语言，
> 但很多地方能明显看出是从原版抄来的。希望模组能'理解'房间结构的组成部分
> 和构建逻辑，进行有机重组。"

---

## 1. 现状诊断：为什么 v3.6 读起来像"拼贴"

v3.6（条带马尔可夫合成）把原版房间切成 48×4 横条带直接入库、按转移表拼接。
问题本质：**内容级复用** —— 条带是原版房间的"实物切片"，包含原版特有的
装饰布局、墙段排列、物件摆放。拼接后：
- 相邻条带来自不同原版房间 → 上下文的装饰/墙线"对不上"，一眼穿帮；
- 同一张条带反复出现（库内高频条带）→ 玩家很快认出"这段是原版 X 房间的"；
- 生成没有"意图"——条带是什么就拼什么，模组不理解自己在建什么。

**破局点**：不复用内容，复用**规律**。原版房间的"内容"是构件（墙带、装饰排、
水池、门洞、分区），"逻辑"是构件组合规则。生成器应当：从语料学规则 → 用规则
现场绘制构件 → 每次产出全新但"懂行"的房间。

## 2. 构件级实证（525 房语料统计，build/corpus-analysis.py + 本规划补充测量）

### 2.1 水平墙带（分区墙）—— 房间的"骨架"
| biome | 每房条数 | 厚度分布 | 覆盖率(占行宽) | 带内缺口 |
|---|---|---|---|---|
| stable | 4.7 | 1格厚占 116/150 | 0.38 | 0（实心段） |
| sewer | 5.3 | 1格厚占 77/119 | 0.34 | 0 |
| plant | 3.4 | 1格厚占 115/140 | 0.34 | 0 |
| mane | 3.7 | 1格厚占 91/97 | 0.40 | 0 |

**关键规律**：墙带是**实心连续段**（无洞），1 格厚（85%+），只覆盖行宽 1/3-2/5。
**通道 = 墙带两端 + 地图左右边道**，而不是墙带上的洞。

### 2.2 墙带锚定行位 —— 分区的"节奏"
| biome | 墙带出现的行（出现率≥50%的房间） |
|---|---|
| mane | **0(100%) 8(77%) 16(85%) 24(100%)** —— 每 8 行一条，3 个开放分区 |
| sewer | 0(100%) 4(64%) 8(55%) 16(50%) 20(55%) 24(100%) —— 4/20 或 8/16 双模式 |
| stable | 0(94%) 8(53%) 24(97%) |
| plant | 12(50%) 24(64%) —— 单中带为主 |

**关键规律**：分区节奏按 biome 有明确锚点（mane=8 行周期；sewer=双模式；
stable=8；plant=12）。开放分区段数 2.7-4.3（均值 ~3.5）。

### 2.3 其它构件
- **竖带**：罕见 —— 仅 sewer 有 ≥50% 稳定列（col39）；一般 0-2 条、1-2 宽。
- **边缘列**（col1/46）：部分墙条，墙率 0.18(mane)~0.45(sewer)，非整高、带口。
- **装饰密度**（开放格中带后缀的比例）：stable 0.55 / mane 0.41 / sewer 0.35 /
  plant 0.33 —— **非常高**，原版房间几乎被物件铺满。
- **水**：sewer 66 格/房(14/22 房有)、plant 67 格(12/42)、stable 190 格(2/32)。
  水以**成片池**出现（块状 `_*` 行），非散点。
- **Z 层栅格**（`,`/`;`/`:`，s+space 可穿）：语料中罕见（stable 129 处），
  以成行结构出现。
- **台阶**（А/Б）：存在于语料（低频）。

### 2.4 连通方式（可达性事实）
原版房间开放区**全连通**（BFS 从 6 缺口可达全部开放格）。连通由以下共同保证：
墙带不封满（覆盖率<1）+ 边道 + 缺口。v3.6 的 repairConnectivity 已可复用为兜底。

## 3. 原版房间的"构建逻辑"提炼（规则集草案）

把 2 节的规律写成**生成规则**（这就是模组"理解"的东西）：

```
R1 分区：房间 = 2-4 个水平开放分区，由墙带分隔（锚定行位按 biome 采样）
R2 墙带：厚 1（85%）/ 2；覆盖率 0.30-0.45；实心连续段；
         位置 = 锚点行 ±1；x 起点/宽度独立随机 → 每次不同的"带"
R3 通道：墙带两端各留 1-3 格开放（端道）；左右边道不封死；
         必要时（修复阶段）挖 2 宽 L 连廊（v3.6 已有）
R4 边缘：col1/col46 按 biome 概率画部分墙条，避开 (12,·) 缺口区
R5 装饰：开放格按 biome 密度撒后缀（权重取自语料 decor 表）；
         同一行的装饰趋向成排（原版行内 40-70% 连续装饰）→ 装饰"排"而非"点"
R6 水体：sewer/plant 以池状放置（宽 4-12 × 深 1-4 的 `_*` 区域，1-3 池）
R7 竖带：0-2 条，锚定列 {8,24,40}±2，高 6-18，1-2 宽，端留通道
R8 收尾：底行全墙 + 6 缺口强制开放 + 连通修复（v3.6 复用）
```

## 4. 头脑风暴：候选生成范式（对照参考游戏）

### A. 参数化结构采样（**推荐，本规划主线**）
从 2 节的分布直接采样"结构参数"（分区数/锚点/带覆盖率/装饰密度/水池），
再用规则现场绘制构件。**学的是分布，画的是原语** —— 无任何原版切片。
- 优点：实现直接、可控性强、无穿帮；与 Minecraft 洞穴/LC 房间"参数+规则"
  的思路一致；v3.6 的修复层可复用。
- 风险：参数调不好会"规整过头"（机械感）。对策：锚点 ± 抖动 + 覆盖率随机化。

### B. 形状文法（Shape Grammar）扩展
把 R1-R8 写成产生式（`Section → Band + OpenArea + Doorway`），递归展开。
- 优点："理解"最彻底、可解释。
- 风险：文法设计成本高；产出容易矩形化/盒子化；调试难。

### C. 构件级 WFC（非条带级）
把"构件"（1×1 墙格、装饰格、水格、边道格）当瓦片，用原版块统计出的
邻接权重做 WFC。比 v3.6 低一个层级 → 无拼贴。
- 优点：统计上贴近原版、无拼贴；可扩展性最好。
- 风险：WFC 权重需要大量语料统计；运行时代价；输出可能"糊"（无结构意图）。
- 定位：作为 M10 的进阶选项（与 A 混合：A 定骨架，C 填充细节）。

### D. 走廊骨架 + 房间填充（LC 式）
骨架走廊（原版少见全宽走廊，更像分区间的"缺口链"）—— 与 A 的结合点：
R1 的分区其实就是"走廊网络"的变体。不单列。

### E. 深度学习/生成对抗
环境（离线 AIR/AS3 运行时、无训练设施）不现实。**排除**。

### F. 混合：A 为主 + 少量高频条带做"内饰点缀"
在 A 生成的骨架上，从语料条带中**摘取局部小块**（如 4×4 的装饰组/水角）做
内饰增强。保留"原版味道"但主体全程序化。
- 定位：M9 的打磨项，可选。

## 5. 推荐方案：v4 结构语法生成（详细设计）

### 5.1 流程总览（AS3 RRSynth.genGrid 线性分支）

```
1. 结构采样（来自语料分布）：
   biome → {分区锚点集合, 分区数}   （mane:{0,8,16} / sewer:{0,4,8,16,20} 选子集 /
                                       stable:{0,8} / plant:{0,12}）
   → 选 1-3 条锚点行（剔除 0/24 边界），每条：厚度(1|2)、覆盖率(0.30-0.45)、
     x0、带内段数(1-2 段，段间留 1-3 格门洞)
2. 渲染墙带：按参数画实心横带（biome 墙材质权重）
3. 竖带：0-2 条（锚定列 ±2，高 6-18，1-2 宽，端留 1 格道）
4. 边缘条：col1/46 按 biome 概率画，避开缺口行
5. 水体：sewer/plant 1-3 池（`_*` 矩形，宽 4-12 深 1-4，池边允许 1 格浅水蔓延）
6. 装饰：开放格按 biome 密度撒后缀；以"排"为单位（行内连续 2-8 格装饰的
   概率 > 散点概率）→ 复现原版装饰排
7. Z 层栅格行：低频（每房 0-2 行，行内连续 4-12 格 `_;` 等）
8. 收尾（复用 v3.6）：底行全墙 + 6 缺口 + repairConnectivity
```

### 5.2 参数表草案（全部来自第 2 节实测，`RRGrammar` 或新 `RRStructure` 常量）

| 参数 | stable | sewer | plant | mane |
|---|---|---|---|---|
| 锚点行 | {8} +边界 | {4,20} 或 {8,16} | {12} | {8,16} |
| 墙带条数 | 3-5 | 4-6 | 2-4 | 3-4 |
| 带覆盖率 | 0.30-0.42 | 0.28-0.40 | 0.28-0.40 | 0.34-0.46 |
| 厚 1 概率 | 0.85 | 0.80 | 0.85 | 0.90 |
| 装饰密度 | 0.45-0.60 | 0.30-0.40 | 0.28-0.38 | 0.36-0.46 |
| 水池 | 罕见(190格池) | 1-3 池 | 1-2 池 | 无 |
| 边缘墙率 | 0.30 | 0.35-0.45 | 0.25 | 0.18 |
| 竖带 | 0-1 | 0-2 | 0-1 | 0 |

### 5.3 与原版/参考游戏的对照
- **Minecraft 洞穴**：噪声阈值出骨架 —— v4 的锚点行=低频"岩层"，墙带=岩层上
  的局部墙段；装饰=洞穴内散落的植物/矿石簇。同为"分布采样 + 规则绘制"。
- **Lethal Company**：房间由"部件库 + 走廊连接"拼装 —— v4 的分区+缺口链
  等价于 LC 的部件-走廊模型，但部件由规则即时生成而非查库。
- **原版 REMAINS 作者**：手工块拼装 —— v4 学到的是作者的习惯（分区节奏、
  带覆盖率、装饰排），产出"长得像作者手搭、但不是任何一间原版房间"。

## 7. 风险与对策
- **规整过头/机械感**：锚点 ±2 抖动、覆盖率随机化、段间门洞随机 → 每次组合
  空间大（~10^8 级），无重复脸。
- **装饰排过密/过疏**：密度按 biome 采样 + 排长 2-8 随机。
- **水体位置堵路**：水池避开墙带端道 2 格外；修复层兜底。
- **与 v3.6 的回归**：保留 RRStripData 数据文件与 v3.6 分支代码（git 历史），
  若 v4 效果不佳可快速回退。

## 8. 验收标准（M9 完成时）
1. 玩家看不出任何一间生成房来自原版切片（无 48×4 整条重复）；
2. 分区节奏/墙带密度/装饰密度统计上落在原版区间（离线断言）；
3. 6 缺口全连通、出口不堵（BFS 断言，300 房 0 失败）；
4. F5 实机 20 连进无异常、无全墙/全空房间。
