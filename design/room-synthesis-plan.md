# 全新房间生成规划（RRSynth）—— 设计规划，未实现

> 版本: P2 规划（2026-08-18）
> 定位：模组核心诉求——从"样板房间随机重组"升级为**无中生有的全新房间构造**。
> 本文只做规划，不承诺实现细节终稿。

---

## 1. 现状与差距

| 层级 | 现在（已完成） | 目标 |
|---|---|---|
| 模板来源 | 作者手写的房间（stable/sewer 等 24 池） | **程序合成的新房间** |
| 变化方式 | RRCook 变异（同材质互换/属性重掷/缺口统一） | 从零生成合法结构 |
| 组合 | 样板房随机重组 + 均匀变异副本 | 每间房结构本身不同 |
| 风味 | 生物群系混搭（stable+sewer） | 特征可组合（废墟/实验室/巢穴…） |

RRCook 的价值延续到合成阶段：**合成房仍需通过缺口统一、敌人生态、变异
增强**——合成器与现有下游完全兼容。

## 2. 语料文法提取（离线，python）

**输入**：全部 `Rooms/rooms_*.xml`（约 525 rnd 房，每房 48×24 网格）。

**提取目标（文法）**：
1. **瓦片码统计**：fForms/oForms 的使用频率、典型组合（如 `_K-_`、`_L`）。
2. **结构模式（n-gram）**：水平/垂直序列模式（墙体直段、转角、掩体单格、
   平台段）→ "墙壁词典"与"家具词典"。
3. **区域语义**：把网格划为若干功能带（边界、通路、放置区、装饰区），
   统计每种带的典型形态——约束生成时的分区布局。
4. **密度校准**：物件（obj）与遮挡（掩体）密度分布——合成房遵循同分布。
5. **难度映射**：ample 中 lvl/entip 与结构复杂度的关系（高 lvl 房掩体更多？）。

**产物**：`文法 JSON`（瓦片词典/模式集/区域模板/密度参数），与生成器同
版本入库（build/ 下）。

## 3. 生成器设计（AS3，运行时）

### 3.1 架构
```text
RRSynth（合成器）
├─ RRGrammar（离线产物加载：瓦片词典/模式/区域模板）
├─ RRSkeleton（骨架生成）   —— 保证连通/可达/门位
├─ RRFill（内容填充）        —— 墙/掩体/装饰按区域模板与密度
├─ RRObj（物件散布）         —— 箱/敌/陷阱按语义落位
└─ wrap() → 合法 <room> XML（带 options/doors/obj）
```

### 3.2 两条生成路线（可并行探索）
- **路线 A：模板拼接（Grammar-based）**：用"骨架模板"（作者房间中提取的
  区域布局骨架，几十种）× 填充词典随机 → 结构化、质量稳。
- **路线 B：WFC-lite（瓦片约束合成）**：48×24 网格，按瓦片邻接约束
  （来自 n-gram 统计）+ 种子确定性坍缩 → 更"无中生有"，需更强不变量。
- 建议：A 先落地（稳），B 作为进阶（A 验证后推进）。

### 3.3 硬性不变量（复用已验证体系）
1. 48×24 尺寸；
2. 边界缺口统一（左/右=行12，上/下=列23,24）——与 normalizeGaps 同规则，
   保证任意配对连通；
3. **可达性**：从任意空白格可走到至少一个缺口（BFS 验证，失败重生成）；
4. tip/uniq 语义正确（合成房全部按 rnd 房处理；beg0 等由池负责）；
5. with doors：合成房给出**标准门位**（缺口统一后的标准模式），保证
   buildRandomLand 的 pass 连接一致；
6. 种子确定性：整体用 `RRSeed.fork("synth")` 替换 Math.random。

### 3.4 敌人数值学
- 合成房的 options：entip/kolspawn 走 rollEnemies（进入级统一接管），
  合成器不背生态；
- 物件密度按 locDifLevel 趋势（留给 RRObj 阶段）。

## 4. 集成点（复用全部现有链路）

```text
池构建时：
  origPools[file] = 快照
    └─ RRSynth 生成 N 个合成房 → 混入池（合成房池）
       └─ cook.normalizePool（缺口/obj）     [合成器自身已保证，双保险]
       └─ cook.cookPool（变异副本可选）
       └─ cook.rollEnemies（进入级按层）
          └─ LandLoader/Land/buildRandomLand/缺口连通/无限扩展
```

- 合成房比例：可配置（默认 30% 合成房混入池，从"小步"验证性能与
  观感开始）。
- 主菜单 UI 加"合成强度"开关（沿用 RRMenu）。

## 5. 里程碑

```text
M1  语料文法提取工具（python 离线）→ 输出文法 JSON + 质量报告
M2  骨架生成器（路线 A：骨架模板 × 填充词典）→ 离线批量不变量验证
M3  RRObj 内容填充 + doors/options 落位 → 离线验证 + 少量实机
M4  合成房混入池全链路（缺口/变异/生态/无限）+ 实机评估
M5  （进阶）WFC-lite 路线 B
```

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 合成房不可达/穿墙 | 硬不变量 BFS 验证 + selfCheck 双保险 + 生成失败丢弃 |
| 视觉质量差（不像 Remains） | 文法词典取自真实语料 + 区域模板约束 + 强度可调 |
| 性能（合成在进入时） | 合成离线预算（每层 ≤N 房）、失败回退作者房 |
| 与变异叠加失真 | 合成房可选跳过变异副本（纯合成 + 原房变异两条线） |
| 敌人/物件语义错配 | 复用 rollEnemies；RRObj 密度参数全部取自语料 |

---

## 7. 与无限模式 / 深度循环的关系

- 无限扩展的新列/行：从合成房池取房（新层新合成的"新构造"）；
- 深度循环：每层上限可加"合成强度 10%→50%"曲线（越深越"异化"）；
- 生态表已按层渐进，合成房 entip 由 rollEnemies 统一覆盖。

## 8. 需要游戏侧确认的点（实现前）

1. 合成房是否需要 `<obj id='player'>`（出生点）——beg0 由池提供，合成
   rnd 房推测不需要；
2. 天花板/天空房（roof/vert）的合成特殊性——conf 依赖，P2 先只合成
   普通 rnd 房；
3. 地图绘制对超大网格的性能（无限模式扩展至 >50×50 时的 drawMap 开销）。
