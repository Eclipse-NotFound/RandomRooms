# v13：危险度、价值度与游戏内调试

本轮按用户要求把 HTML 中讨论的新机制接入正式 AS3 生成链，已部署并通过独立新实例的原加载器启动检查。安装文件 88,909 B，SHA256 `a5eb49a089835bbc7b670411bbdf32865f5110aeae79f8bc182af3bb4c9cbe46`；时间、备份与重启证据见同目录 `deployment.json`、`runtime-checks.json`。

## 游戏里怎样查看

完全退出并重启游戏，F2 回城，F1 选 **v13**，再选种子与场景。新版本默认使用 v13；v12.2、v12.3 仍可切换对照。已载入的旧地图保持旧内容，需要重新开始探索。

**Shift+F3** 开关调试层，开关状态会保存。单独 F3 仍是原有测试入口。调试信息跟随当前合成房、镜像和镜头移动，在普通原版房、菜单与 Pip 界面中隐藏。

| 显示 | 含义 |
|---|---|
| 房间框、用途、D / V | 当前功能分区与局部危险度、价值度；合并成同一房间的矩形共享数值和预算 |
| 底部合成房 D / V | 整间合成房的基调，内部房间在此基础上变化 |
| 空心十字 | 生成时安排的点位；对象移动、死亡或被搜取后，点位仍保留 |
| 实心点 | 当前存活单位的位置；红色普通敌人、紫色炮塔、绿色友方、灰色关闭的炮塔 |
| 紫色虚线 | 生成器希望炮塔守住的门梯或连接位置 |
| 青色虚线 | 生成器为安保终端预留的候选接近路线 |
| 实线 | 当前武器枪口朝向，碰到现有实体墙体截断；随瞄准移动，关闭的炮塔不画活动枪线 |

枪线不是命中预测：它没有计算弹丸散布、弧线、穿透或敌人的下一次转向。终端候选路线也不是战斗保证：后续走动的敌人、破坏掩体或开箱事件会改变现场。

## 接入的机制

- 延用 v12.3 的真实地形：用途分区、随机数量与大小、对齐楼层、厚实体块和矩形合并；没有把 HTML 简化示意地形替换进游戏。
- 合成房基调与局部 D/V 分开抽样，共同因素占 30%，局部变化幅度 32，另有用途偏向。高危低值、低危高值都可出现。
- D 控制主要敌群出现机会、规模与布防，原版场景生态和探索难度继续决定敌人型号。V 控制额外高价值容器出现机会，不保证开出某种物品。
- 每个最终合并房共用一份压力预算，避免拆成多个矩形后重复加怪；主要敌人每合成房最多 10 个，特殊威胁最多 3 个，炮塔最多 3 个。
- 普通零散动物独立抽取出现机会；蜘蛛地雷、地雷、无人机等另走特殊规则，偏向低 D、高 V 的区域。地雷类优先选择从入口、门梯位置不易直接看到的候选点。
- 顶装、地面炮塔统一按战术位置筛选，检查安装支撑、真实机械转角、门梯目标及入口缓冲。原生普通敌池里抽到的炮塔也不能绕过这套规则。
- 有炮塔的合成房有 62% 机会尝试放安保终端，每合成房最多一台；找不到合适位置就不硬放。控制范围遵循原版：整间 Location 内的所有炮塔。
- 终端操作位优先控制室、检修或办公空间，避开全部炮塔可转向射界，要求有支撑、避开梯子吸附和门梯预留区，并存在一条来自实际开放入口的避火步行/梯路。每个入口的可达状态分别记录，其他入口不保证全程避火。
- 保留原版可用的终端、奖励箱、陷阱电路、警报/机器人舱及补给设施；不引入剧情 NPC、任务装置或首领。

出生房与展示馆不放初始敌群。原版容器自带的暗雷、开箱刷怪和奖励随机仍然存在；低 D 不能理解成绝对安全。D/V 也不是对玩家装备与技能的自适应难度。

## 验证依据

所有原版运行都在独立 `pferr-style-*` AIR 应用中完成，使用新测试角色。驾驶器与待部署 SWF 分开编译，不修改正式 SWF 加测试分支；根游戏 SWF、真实存档、其他模组保持原样。主机制候选 `50747c20…e261b`，最后发布候选 `a5eb49a0…cbe46` 仅调整顶炮调试文字的纵向位置，生成及控制逻辑相同。

| 检查 | 结果与证据 |
|---|---|
| 真实 AS3 批量生成 | 192 间，47 座炮塔、17 台安保终端；预算、合并组、安装、终端路线检查通过。`algorithm-checks.json`、`algorithm-evidence.zip` |
| V 独立性 | 固定其他输入、V=0 与 100 共 32 对；地形、生态、主敌群与炮塔不被价值变化重抽 |
| 旧版回归 | 1024 间历史 XML 重放一致；512 个实际坐标输入通过，256 对版本输入一致、896 对邻接口一致；v12.2 七文件与哈希核验的旧发布证据一致 |
| 三版本原生界面 | F1、F4、回城切换、随机选择、F5 与取消/暂停共 12 案通过，见 `ui-lifecycle-final` |
| 四场景原生物体与调试 | 连续 4 案通过；生成点对应真实对象、镜像、D/V、标签完整、原生机关/终端/开箱效果以及炮塔停机后的枪线通过，见 `population-release-candidate` |
| 实际终端操作位 | 工厂样例用普通移动抵达，互动范围与原生射线检查通过，见 `terminal-approach-plant` |
| 最后文字调整 | 工厂调试与互动复测通过，并查看真实画面确认 D/V 未被顶炮文字覆盖；见 `overlay-final` |
| 右下扩张往返 | 四场景各完成新列、新行往返，均从 5×5 扩到 8×8，原 XML、镜像、旧物体保持；下水道 wetFrames=0。见 `growth-final` |
| 正式文件重启 | 安装后通过原有清单加载器启动，F1/F4/F2/F5 与 Shift+F3 共 3 案通过；驾驶器不调用模组 init，见 `release-smoke` |

成功结果不能覆盖此前失败：

- `terminal-ladder-failed`：终端操作点贴着梯子，角色吸附后露出掩体。修正真实选点规则，`terminal-approach-plant` 同种子复测通过。
- `navigation-flight-failed`：测试驾驶器在斜梯下方追逐不能直接落脚的节点反复折返。补充梯脚较远且被家具挤占时的走法，不改游戏地形或移动角色坐标。
- `ui-clock-gap-failed`：前 11 案通过，最后一案出现长时间心跳空档后超时，原因未确定；独立新实例完整 12 案复测通过，没有把超时那轮报成成功。
- 早期连续测试曾在区域切换尚未结束时请求回城，原版世界和目标 ID 会失配。正式 F2/F4 现会等待切换结束，驾驶器也检查原生切换状态；四场景连续交互复测通过。
- 早期调试文字第二行被裁切，已开启多行并检查文字高度；最后进一步下移顶炮文字，避免盖住房间 D/V。
- `native-loader-readiness-failed`：新增启动检查器等待了不存在的启动期随机房池，原加载器其实已成功初始化模组。按门禁先回滚，修正为等待本实例 READY 证据后重新部署，同一 SWF 完整重启检查通过；未改生成器来迁就检查器。

这些测试不等于穷尽所有种子、所有进入方向或长期无限扩张。尚未验证本轮与全部其他模组同时运行、联机或长期内存上限。自然度、战斗密度和奖励分布仍需实际游玩反馈。

## 构建、复现、回滚

构建：`build/build-v7.ps1 -OutputName RandomRooms-v13-release-candidate.swf`。发布入口固定 `release/RandomRoomsMod.swf`；候选与部署必须逐字节一致。

算法验证：`build/style-review/harness/run-comparison.ps1 -Content`；旧版验证省略 `-Content`。冻结脚本 `build/style-review/freeze_v13_algorithm.py` 使用本轮记录的候选指纹，防止拿下一次生成结果覆盖这次证据。

原生检查入口：`build/style-review/game-harness/run-game-captures.ps1 -DevelopmentSwf <SWF> -GeneratorVersion 13`，按需附加 `-AllScenes -PopulationProbe -ContentGallery`、`-AllScenes -NavigationProbe -GrowthProbe`、`-TerminalApproach -Scene plant`、`-ComparisonLifecycle`。`-NativeLoaderSmoke` 走原游戏加载清单，检查 F1/F4/F5 与 Shift+F3，不直接调用模组的测试入口。

旧正式版已备份：`build/release-backups/RandomRoomsMod_before_v13_20260928.swf`，SHA256 `8e0e8a83e0de96d0ca6f5162dd81f226b53cf8f0634f0ad073e9e3829ba292e9`。回滚须完全退出游戏，复制备份到 `release/RandomRoomsMod.swf`，核对哈希，重启后进入新地图。实际备份和部署完成时间见 `deployment.json`。
