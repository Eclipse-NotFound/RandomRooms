## 2026-09-04 v6.3 门原版墙顶模式 + 背墙校验重做 + 缺口贯通隧道

- 实机反馈："问题未被修复"+补充"合成房边界处无法看到缺口"。
- 诊断（反编译源码全链路实证，本轮关键突破）：
  1. 玩家跨合成房机制 = **像素撞边**：Unit.moveX 中 `X-scX/2<0` → outLoc(1) →
     Land.gotoLoc → 目标 loc 同高度边缘位（x=limX-9 或 x=9，y=玩家原 Y）→
     **collisionUnit 过碰撞才放行，否则 return null 玩家弹回**。
  2. 我们的边界 = 整圈墙 + 3 个 2 格缺口（左右开放率 4%）——玩家在 96% 的
     高度撞边都被弹回 = "无通道"；且整墙边界视觉上**根本没有可见缺口**。
  3. 原版作者房边界开放率（658 房统计）：**L/R 35%（~8.7 格）、T 30%、B 16%**
     ——多高度段可穿行，边界开口可见。
  4. v6.3 的缺口隧道修的是缺口内侧（必要不充分）；弹回发生在边界碰撞检查。
- 实施（v6.4）：
  - 边界改**原版式开放段**：GY/GX 锚点 + 左右 2 段×3-6 格 + 上 2 段×4-7 格 +
    下保守 1 段 3-4 格（下边界走出=坠落死亡，原版开放率也最低 16%）；
  - 每个开放边界位向内逐位挖贯通隧道（1 宽×≤6 步接上开放区）；
  - verifyEntry 检查改运行时 Location.space 四边 phis 开放数（原 XML 检查
    #1034 根因：locs[..].room 是运行时 Room 对象非 XML）。
- 离线断言（300 房最坏全墙 grid）：贯通不足 0；开放位 L/R 8.6（原版 8.7）、
  T 11.6、B 5.3——与原版对齐。normalizeGaps 只开不关已确认不冲突。冒烟通过。
- 待实机：边界开口可见性、跨合成房行走、日志"边界通行"行。
